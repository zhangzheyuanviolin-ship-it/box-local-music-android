一、用户最初需求与项目背景
用户要求处理两个 Android 项目的功能融合。
第一个项目是用户 GitHub 账号下的“本地智能体广场”，最初来源于 Google 官方 AI Edge Gallery，并已经做过深度改造。用户描述该项目保留了 AI 聊天、智能体任务、图像问答、音频转写等原有任务，同时新增视觉旁白、AI 键盘、视频问答、本地图像生成、视觉创作、更多模型列表、更多智能体工具和多种网络搜索工具。用户要求任何新增融合工作不能破坏本地智能体广场已有功能。
第二个项目是第三方开源项目 Box。用户描述 Box 也来源于 Google AI Edge Gallery，并加入本地图像生成、本地音乐生成、物体检测、本地翻译、本地音频转写等功能，且使用多套本地推理引擎。用户说明 Box 云端开源仓库与发布 APK 不完全对应，因此需要结合手机本地资产、APK 分析材料和云端仓库一起处理。
用户的最终融合目标是把 Box 中本地智能体广场尚未覆盖的功能模块吸收进本地智能体广场。用户指定最初优先级是本地音乐生成，其次是 Box 中三个额外的大图像生成模型，再次是 LiteRT/LiteRT-LM 推理引擎版本和其他模型列表及推理引擎。

二、用户指定的工作约束
用户明确要求不要在主分支做功能融合，应基于本地智能体广场的 experimental 分支处理，因为手机当前安装的本地智能体广场包名带 mcp 后缀，来自 experimental 分支构建产物。
用户明确要求不要在手机本地完整构建安装包，标准流程是本地修改代码后推送到云端 GitHub Actions workflow 构建，再把产物下载回手机本地归档。
用户明确要求产物、日志等归档在用户共享存储根目录下的“下载管理”文件夹，不是 Download 文件夹下的“下载管理”子目录。

六、Box 音乐生成功能已定位到的代码事实
在 jadx 反编译源码中，SoundGen 基础模型状态类为 p000/OlI1OoIO0.java，SoundGen HD 状态类为 p000/OlI1Il1.java。
在 jadx 反编译源码中，SoundGen 基础引擎相关类包括 p000/OlI0OO1.java，加载 sg_text.litert、sg_core.litert、sg_decode.litert。
在 jadx 反编译源码中，SoundGen HD 引擎相关类包括 p000/OlI0lo1OOoiO.java，加载 sghd_text.litert、sghd_core.litert、sghd_decode.litert、sghd_vocab.spm。
在 jadx 反编译源码中，HD/Long 模型定义相关类包括 p000/OlI10oI0oO01.java，其中可见 SoundGen HD 使用 dit_L256_int8.tflite 和 ae_dec_L256_int8.tflite，SoundGen HD Long 使用 dit_L2048_int8.tflite 和 ae_dec_L2048_int8.tflite。
在 jadx 反编译源码中，任务定义相关类 p000/Ii11101IOi.java 中可见 soundgen、soundgen_hd、soundgen_hd_long 等任务标识和说明文案。
在 smali 中，HD/Long 共用页面类为 /data/user/0/com.codex.mobile.pocketlobster.test/files/home/codex/box-optimized-v333/apktool/smali/iO10II1oIll0.smali。
在 smali 中，基础 SoundGen 页面类为 /data/user/0/com.codex.mobile.pocketlobster.test/files/home/codex/box-optimized-v333/apktool/smali/iO10OIiI0i.smali。
在 smali 中，HD/Long 的时长 Slider 回调类为 /data/user/0/com.codex.mobile.pocketlobster.test/files/home/codex/box-optimized-v333/apktool/smali/OlI11I0.smali，该回调中把 Float 转 int，并通过 clamp 约束到 1 到 200。
在 smali 中，基础 SoundGen 的 Slider 上限为 11.0f；这不是用户本次要求修复的 24 秒和 3 分钟两个 HD/Long 模型问题。
在 smali 中，HD/Long 页面会从引擎对象 LOlI0o1 的 I0000oI00 字段读取最大秒数，若对象为空则回退到 0x17，即 23。
在 smali 中，LOlI0o1 构造函数用输入块数乘 0x1000 后除以 0xac44，即按 44100 采样率换算秒数。
在 smali 中，LOlI10loO0oio.smali 中可见短 HD 使用 0x100 作为 LOlI0o1 构造参数，Long 使用 0x800 作为 LOlI0o1 构造参数。

七、本地智能体广场融合音乐生成阶段的已发生事实
用户指定第一个融合版本聚焦本地音乐生成模块，要求接入 Box 三个音乐生成模型，新增音乐生成入口，并尽量复现 Box 的下载、生成、播放、导出、分享逻辑，同时修复 Box 原版中 HD 和 Long 滑块上限问题。
前期曾进行多轮本地智能体广场 experimental 分支修改与云端构建。用户反馈有“七轮构建全部失败”的阶段。当前文档未逐条记录七轮构建的每条 GitHub Actions 错误日志，原因是当前上下文没有完整逐轮日志文本。
后续调整后，曾产出可安装到 com.localagent.plaza.mcp 的本地智能体广场版本。用户测试过一个版本，主页面显示“本地音乐生成 任务，包含 0 个模型”，点击音乐生成模块无反应。
后续又产出过一个版本，用户测试反馈能够看到三个模型，能够进入音乐生成页面，并且前两个模型能够正常下载。
用户测试反馈第一个约 1.1GB 的 SoundGen 模型可以生成约 11 秒音频，但生成结果是噪音或无意义声音，不是正常音乐。
用户测试反馈第二个约 2.2GB 的 SoundGen HD 模型曾经出现“生成失败：Index 1 out of bounds for length 1”。
后续版本中，用户反馈“Index 1 out of bounds for length 1”问题已解决，两个模型都能完成生成流程。
用户继续测试后反馈，两个模型虽然能生成音频，但生成结果仍然是噪音或支离破碎的损坏音频效果，不符合 Box 官方应用同模型生成效果。
用户明确指出官方 Box 应用中同样提示词能生成有意义音频，较大的 SoundGen HD 模型能生成质量较高、有旋律和和声的钢琴曲片段；本地智能体广场融合版本不能做到。
用户提供过一个由失败融合版本生成并保存的音频文件事实：Music 文件夹中 SoundGen_1786457587425.wav，大小约 2.1 MB，用户描述该文件是噪音。
在上述阶段中，用户明确指出模型文件位于各应用私有目录，Box 官方应用已下载的模型不能复制给本地智能体广场共用，本地智能体广场必须重新下载模型。

十、Box 原版逆向优化实验中已遇到的工具链错误事实
apktool 2.7.0 初次 build 时在 smali 阶段报错：iO10II1oIll0.smali 中 if 比较使用高号寄存器 v42，错误信息为“The maximum allowed register in this context is list of registers is v15”。随后补丁改为先 move/from16 到低号寄存器后比较。
apktool 2.7.0 后续 build 在 smali 阶段出现 Java heap space OutOfMemoryError。随后使用 -JXmx4096M 提高堆内存。
apktool 2.7.0 在资源构建阶段使用旧 aapt 报资源名非法，资源文件名含 $，例如 res/drawable/$avd_hide_password__0.xml。
下载并使用 apktool 2.12.0 后，自带 aapt2 在 Android arm64 Ubuntu 环境中执行时报 exit code 132。
改用 Ubuntu 系统 /usr/bin/aapt2 后，aapt2 仍然拒绝带 $ 的资源文件名。
曾机械重命名 res/drawable 下带 $ 的 XML 文件为 dollar_ 前缀，并同步替换 XML 引用和 public.xml 中的 name。
使用 apktool 2.12.0 和系统 aapt2 时，系统 aapt2 不识别 apktool 传入的 --no-compile-sdk-metadata 参数。
曾写入 aapt2_strip.sh wrapper 过滤 --no-compile-sdk-metadata 后调用 /usr/bin/aapt2。
随后 aapt2 link 阶段报 Android 私有颜色资源错误，例如 android:color/bright_foreground_dark_disabled、android:color/btn_default_material_dark 等资源为 private。
曾从手机系统复制 /system/framework/framework-res.apk 到工作区，并用 apktool if 安装到独立框架缓存。
使用设备 framework-res.apk 作为 include path 时，aapt2 报 “RES_TABLE_TYPE_TYPE entry offsets overlap actual entry data”和“Failed to load resources table in APK”。
上述资源构建相关错误发生在完整重编 resources.arsc 路线中。
