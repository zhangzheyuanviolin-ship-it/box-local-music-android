1.2 起源与定位
--------------
Box 是 Google AI Edge Gallery 的二次 fork（衍生作品）。
- 上游：Google AI Edge Gallery（Google 官方开源项目，展示 LiteRT 在 Android 上的能力）
- 下游：Box 团队在保留 Google 所有 LiteRT 模型能力的基础上，叠加了：
  * 自定义应用壳（com.box.gallery 命名空间）
  * AgentChat 模块（多轮对话与函数调用）
  * MobileActions 模块（系统级工具桥接：手电筒、联系人、短信、地图导航、摄像头等）
  * TinyGarden 模块（一个独立的小游戏 / 沙盒实验场）
  * 主题系统（Catppuccin / Dracula 等自定义主题）
  * 数据库层（Room / SQLite，用于历史记录持久化）
  * 认证系统（本地认证，无后端服务器依赖）

  其 packed-switch 0/1 分别对应 SoundGen 和 SoundGen HD 两种调用模式

5.1.6 推理特性
- 输出分辨率：256×256（16×16 latent grid）
- Guidance-free：只跑条件正路，2 个 forward 不跑无条件负路，节省 50% DiT forward 次数
  这是 FLUX.2 klein 区别于原版 FLUX 的核心创新
- 4 步 DiT 采样（实际 8 个 forward：4 个单流 + 4 个双流）
- GPU 优先 + CPU fallback
- 进度回调：通过 Function1.invoke(Float) 上报，UI 显示 "Generating image..."

5.1.7 与其他 FLUX 实现的对比
- FLUX.1 schnell（官方）：1-4 步采样，需要 CFG
- FLUX.1 dev（官方）：20-50 步采样，需要 CFG
- FLUX.2 klein（社区）：4 步采样，guidance-free，本地友好

6.0 共同架构：AudioLDM / Stable Audio 风格 Latent Diffusion
--------------------------------------------------------------
所有三个音频模型都遵循 latent diffusion 模式：
  文本 → Text Encoder → Cross-Attention Conditioning → DiT/UNet 1D
  → 反向扩散 8/N 步 → Latent → VAE Decoder → Waveform (PCM)

HF 仓库：jegly/audio（社区）
辅助仓库：jegly/noise（提供 Gaussian 噪声）

  * I00Ol10 : I - packed-switch 索引
  * I00Ol1ll1 : String - prompt
  * I00OloOo : Function1 - 进度回调
  * I00i01iIIliI : J - seed
  * I00i0O : F - 强度
  * I00i0ilIl0i : Context - 上下文
  * I00i0oil : Object - 引擎持有（OiIiIIOOiO 或 OiIiIl0）

6.1.5 SoundGen 推理循环细节
- BPE 分词阶段：行 494-800，标准 SentencePiece BPE 算法（拼字符 + 查 BPE 表 + 替换 + 过滤 + 转换 UTF-8）
- 采样阶段核心参数：
  * 0x100 = 256 - mel bins 频谱维度
  * 0x1000 = 4096 - 中间隐藏维度
  * 0x45700000 = 3840.0f - 标准差基准
  * 0x3f000000 = 0.5f - 缩放偏置
  * 0x3d4ccccd = 0.05f - 强度默认值
  * 0x3f266666 = 0.65f - 高斯 sigma 计算系数
  * 0x3f4ccccd = 0.8f - 默认 CFG scale
  * 0x41000000 = 8.0f - 默认 diffusion 步数
- 关键循环变量：v1 < 0x8（行 1638-1642）— 8 步 diffusion 循环
- Sigma schedule：8 元素 [F 数组（行 1332 new-array v7, v7, [F，其中 v7=9-1=8 个实际值）
  - 最后一个元素强制 = 1.0f
  - 标准 AudioLDM timesteps = [1.0, ..., 0.0] + Karras sigmas
  - 计算公式：Math.exp(...)（行 1321）
- 噪声采样：java.util.Random(seed).nextGaussian()（行 1466）
- 模型调用：3 次 CompiledModel.run$default
  * 第 1 次（行 418）：text encoder
  * 第 2 次（行 690）：DiT core
  * 第 3 次（行 843）：VAE decoder

6.1.6 推理特性
- 输出时长：约 24 秒
- 采样步数：8 步
- CFG scale：0.8（默认）
- 强度：0.05（默认）
- 隐层维度：3840
- Mel bins：256

第七部分  统一推理后端：Google LiteRT
================================================================================

7.1 LiteRT 架构
---------------
- 包名：com.google.ai.edge.litert.*
- 核心类：
  * CompiledModel - 已编译的 LiteRT 模型（封装 native 模型句柄）
  * CompiledModel$Companion - 工厂方法 create(模型路径, Options, Environment)
  * CompiledModel$Options - 编译选项（Accelerator 数组）
  * CompiledModel$GpuOptions - GPU 选项（Precision, BufferStorageType, Priority 等）
  * TensorBuffer - 输入/输出张量缓冲区
  * Environment - LiteRT 运行时环境
  * Accelerator - 加速器枚举（GPU / CPU / NPU）
  * JniHandle - JNI 句柄基类（提供 close() 方法释放 native 资源）

7.2 GPU 编译选项
----------------
所有模型的 GPU 编译都遵循统一配置：
  GpuOptions(
    precision = FP32,        // 浮点精度
    priority = 0x7ff7 (32759),  // 最大优先级
    // 11 个 Boolean 字段（advanced settings）
    // 1 个 Integer 字段（priority）
    // 2 个 String 字段（shader 路径 / cache 路径）
  )
  
  Options(
    accelerator = [GPU, CPU]  // 优先 GPU，失败回退 CPU
  )

7.3 三件套调用模式
------------------
所有推理都遵循以下三件套模式：
  1. compiledModel.createInputBuffers(2) - 创建输入缓冲区（2 个 buffer：cond + noise）
  2. compiledModel.createOutputBuffers(2) - 创建输出缓冲区（2 个 buffer：denoised + log_var）
  3. compiledModel.run(inputBuffers, outputBuffers) - 执行推理
  4. 读取 outputBuffers.get(i).readFloat() - 获取结果

7.4 GPU→CPU Fallback 模式
-------------------------
- 加载时优先 GPU（Accelerator.GPU）
- GPU 编译失败时自动重试 CPU（Accelerator.CPU）
- 日志格式："<model_tag> failed to compile on GPU, retrying on CPU"
  其中 model_tag 是：
  * "FluxKleinEngine" - FLUX.2 klein 引擎
  * "ZImageEngine" - Z-Image 引擎
  * "SoundGen" - SoundGen 引擎
  * "SoundGen HD" - SoundGen HD 引擎
- 完整加载成功的日志：
  * "SoundGen: all components loaded" - SoundGen 全部 4 个组件加载完成
  * "SoundGen HD: all components loaded" - SoundGen HD 全部 4 个组件加载完成
- 失败兜底日志：
  * "Failed to load FLUX.2 klein (check that all files finished downloading)" - FLUX.2 下载未完成

7.5 原生库依赖（52 个 arm64-v8a .so）
-------------------------------------
关键 .so 文件：
- liblitertlm_jni.so - LiteRT JNI 桥接（核心）
- libQnnHtpPrepare.so - 高通 NPU（Qualcomm Hexagon Tensor Processor）
- libggml-vulkan.so - Vulkan GPU 委托
- libonnxruntime.so - ONNX Runtime（备用推理后端）
- libstablediffusion.so - Stable Diffusion 原生 C++（23MB，专用 Stable Diffusion 路径）
- libvulkan.so / libOpenCL.so - Vulkan / OpenCL 系统库
- libEGL.so / libGLESv3.so - EGL / OpenGL ES 系统库

7.6 Stable Diffusion vs LiteRT 双轨并行
----------------------------------------
Box 中存在两套并行的本地生成推理后端：
1. LiteRT (.tflite) - 用于 FLUX.2 klein / Z-Image / SoundGen 全家
2. libstablediffusion.so (原生 C++) - 用于 Stable Diffusion 模型（用户文案中提到的 stable 路线）

两者在代码层面完全独立：
- LiteRT 路径：Java 层通过 CompiledModel API 调用
- Stable Diffusion 路径：Java 层通过 JNI 调用 libstablediffusion.so

7.7 模型下载流程
----------------
1. 用户在 UI 选择要使用的模型（FLUX.2 klein / Z-Image / SoundGen / SoundGen HD / 等）
2. Box 检查本地缓存目录是否已有对应模型文件
3. 如无，启动 HuggingFace Hub 下载：
   - 仓库 URL：https://huggingface.co/litert-community/FLUX.2-klein-4B-LiteRT
                https://huggingface.co/litert-community/Z-Image-Turbo-LiteRT
                https://huggingface.co/jegly/audio
                https://huggingface.co/jegly/noise
   - 文件 URL：https://huggingface.co/<org>/<repo>/resolve/main/<filename>
   - 下载策略：流式下载 + 断点续传 + 完整性校验（SHA256）
4. 下载完成后，Box 将文件重命名为本地命名（如 sg_core.litert / sghd_core.litert）
5. 引擎类加载本地文件，编译成 LiteRT CompiledModel
6. GPU 优先，失败回退 CPU
7. 推理完成后释放资源（close JniHandle）
